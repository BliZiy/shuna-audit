Method

  1. Make up to 80 small mutants of each reference solution (flip comparisons, arithmetic, and/or, ±1 on integer constants, drop not).
  2. Keep mutants that pass every official test (for EvalPlus: match the reference on all ~1000 base+plus inputs).
  3. Fuzz: perturb official test inputs and find one where mutant and reference differ (a witness).
  4. Confirm independently: re-run the mutant's version of the original function on EvalPlus' validated, contract-respecting inputs. Disagreement = verified · oracle. Where no oracle exists, a documented spec review = verified · review.

Debate check

Before anything is confirmed, a prosecutor pass re-runs the evidence and a defender pass tries to refute it: D1 the reference passes and is deterministic; D2 the witness input looks like the official inputs (types, value ranges, characters, lengths); D3 the task wording (positive, sorted, distinct, non-empty…) is not violated; D4 the difference is not just a timeout or float noise; D5 for Pro tasks the final answer, not only the helper, is wrong. The prosecutor gets one retry with a conservative fuzz drawn from official inputs. Survivors still need an independent oracle or manual review.

False-positive policy

  • Suspected items are never counted.
  • Verified-review relies on our reading of the spec and on the reference being correct.
  • This measures test strength. It does not show that any model actually exploited a gap.
  • Maintainers can dispute any item. Disputed items stay listed with their status.

Code, data hashes and a one-command re-run are in the repo (link added at publication).
